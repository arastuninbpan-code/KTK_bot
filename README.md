# Расписание театра: Google Таблица → уведомления в Telegram и MAX

Администратор ведёт расписание в Google Таблице, как и раньше. Сотрудники подключаются к боту (Telegram и/или MAX)
и получают сообщение при любом изменении в их сменах. Ни приложения, ни сайта нет. Менять что-либо через бота нельзя:
он только присылает уведомления и показывает расписание.

## Что умеет бот
- Уведомления: 🆕 вас назначили · ❌ сняли · ✏️ перенесли время/зал · 📅 напоминание **за сутки** и ⏰ **за час** до смены.
  Время берётся из первой колонки (при нескольких, например «11.00 и 13.00», — самое раннее).
  Если времени в строке нет, напоминание одно: накануне в 18:00. Каждое напоминание приходит один раз.
  Только что добавленную смену «за сутки» уже не напоминают, если до неё меньше суток: придёт «вас назначили» и потом «за час».
- Команды: `/shifts` — мои смены, `/schedule` — афиша с составом, `/stop` — отключить уведомления.
- Подключение: `/start` → кнопка «Поделиться номером» (или номер текстом). Номер должен быть в листе «Сотрудники».
  Один человек может подключить и Telegram, и MAX: уведомления придут в оба.

## Таблица
Менять привычный вид не нужно. Приложение читает лист **«Расписание»** в том виде, как его ведёт театр:

| Дата/Время | Спектакль/Сцена | Администратор/Капельдинер | Гардероб/Уборщица | Касса | Монтировка | Актеры, свет, звук |
|---|---|---|---|---|---|---|
| 04.10 11.00 и 13.00 | Спектакль «Бука» (малая сцена) | Иванова М.В. | Морозова Н.М. | Орлова А.В. | | |

- Роль берётся из заголовка колонки, зал — из скобок «(малая сцена)», время — из первой колонки.
- Несколько людей в ячейке: `Иванова А.А./ Петрова Б.Б.` или через пробел — разберётся.
- Диапазон `25.10 до 31.10` разворачивается по дням. Пустые дни пропускаются.
- Если в одной строке два события (например, репетиция и экскурсия), они считаются одним событием с общим составом.
- Заголовки колонок можно переименовывать — роли в уведомлениях будут называться так же.
- Альтернатива: плоский вид `Дата | Время | Событие | Зал | Роль | ФИО` (определяется автоматически по слову «Зал» в 4-й колонке).

Лист **«Сотрудники»**: `ФИО` (точно как в расписании) и `Телефон`. Кого нет в списке — войти не сможет; убрали из списка — доступ пропадает.
Программа в таблицу ничего не пишет: сервисному аккаунту достаточно доступа «Читатель».

## Демо (без мессенджеров и Google)
```
pip install -r requirements.txt
python main.py --demo
```
Вводите `1: /start`, `1: контакт +7 900 000-00-01`, `1: /shifts`; `time +30h` двигает часы. Правьте `demo/schedule.csv`.

## Как это работает без сервера
Бот запускается на бесплатных **GitHub Actions** (репозиторий публичный, лимита минут нет). Ему нужен «будильник»:
маленький скрипт в самой Google Таблице (`apps_script/Code.gs`) запускает бота
- через ~20 секунд после последней правки таблицы (пауза нужна, чтобы не слать уведомления о недописанной правке);
- каждую минуту: бот отвечает на сообщения и присылает напоминания.

Итого уведомление приходит примерно через минуту после правки. Подписчики и «что уже отправлено» бот хранит в
служебных листах той же таблицы («Подписчики» читаемо, «_служебное» — технический). Их не удалять и не править.

## Настройка (один раз)
1. **Публичный репозиторий.** Settings → General → Danger Zone → Change visibility → Public.
   Секретов в коде нет: всё лежит в Secrets (п. 4) и в таблице.
2. **Google Cloud.** Создать проект → включить Google Sheets API → IAM → Service Accounts → создать аккаунт → Keys → JSON.
3. **Таблица.** Листы «Расписание» и «Сотрудники» (см. выше). Открыть доступ **«Редактор»** на email сервисного аккаунта
   (нужен, чтобы бот вёл служебные листы; в «Расписание» и «Сотрудники» он ничего не пишет).
4. **Секреты репозитория** (Settings → Secrets and variables → Actions → New repository secret):
   `TELEGRAM_BOT_TOKEN`, позже `MAX_BOT_TOKEN`, `SHEET_ID` (из ссылки на таблицу), `GOOGLE_CREDENTIALS_JSON` (всё содержимое JSON-ключа).
5. **Будильник в таблице.** Расширения → Apps Script → вставить `apps_script/Code.gs`. Создать токен GitHub
   (Settings → Developer settings → Fine-grained tokens → только репозиторий KTK_bot → Actions: Read and write) и сохранить его
   в Apps Script: Свойства проекта → Свойства скрипта → `GH_TOKEN`. Один раз запустить функцию `setup()` и выдать разрешения.
6. Проверка: Actions → bot → Run workflow. Затем написать боту `/start`.

Обычный сервер вместо Actions тоже подойдёт: `python main.py` работает постоянно (в `.env` те же переменные).

## Тесты
`pip install -r requirements-dev.txt && python -m pytest`

## Не проверено вживую
Клиенты Telegram и MAX написаны по документации и проверены только на тестовых заглушках. Особенно стоит проверить
кнопку «Поделиться номером» в MAX (формат контакта) — если она не сработает, работает ввод номера текстом.
